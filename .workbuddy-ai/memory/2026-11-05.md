## Code review (read-only): performance bottlenecks + correctness bugs

Reviewed whole app (`app/`, `resources/views/pages/**` Livewire 4 single-file components, `app/Console/Commands`, migrations). No files changed; working tree already had unrelated uncommitted edits before the review.

Top verified findings (all with file:line, reported to user):
- `LedgerService::statementTotals/cashCounterpartyTotals` use `whereDate()` on a `date` column → non-sargable, defeats `posted_on` indexes; whole-book scans behind every statement.
- `ClosePeriodValidation` runs `Artisan::call('reports:tie-to-ledger')` synchronously per render; that command does 2 queries/trip + 1 ledger aggregate/bill.
- `MonthlyRevenueAndExpense` calls `profitAndLoss()` once per month → 6 full ledger scans on the dashboard (budget raised to 100 queries/800 ms in `config/performance.php`).
- N+1: `LiveMap::vehicles()` per-position `FleetDirectory::truck()`; `fuel` pages `litresRemainingX100()` per purchase; `settlements` `tripNo()` per row; `work-order` `issuedParts()` called twice (not `#[Computed]`).
- Unbounded reads: dashboard `expiring()`, trip `waybills()`, dispatch `jobChoices()`, vehicle `travelled()`, `CashForecastQuery`, `InvoicesRecomputeBalances`.
- Bug: `IssueCreditNote` treats a foreign invoice's document-currency minor units as base currency (no guard; `AllocatePayment` does have `settleForeign`).
- Bug: `closed` periods have no DB backstop (trigger refuses only `locked`) and `LedgerService::post()` does an unlocked, pre-transaction period read → TOCTOU.
- Bug: idempotent Actions (`IssueInvoice` et al.) check `source_uuid` outside the transaction and never catch `UniqueConstraintViolationException`; Laravel 13 `ConcurrencyErrorDetector` does not retry 1062 → 500 on concurrent retries. `LedgerService::post()` does catch it correctly.
- Bug: period transitions (`ClosePeriod`/`LockPeriod`/`ReopenPeriod`) are read-check-save with no lock.
- Bug: POD file bytes written inside an outer `DB::transaction`; a later rollback leaves orphans.
- Bug: `DispatchGate` mixes Gaborone business day with UTC `whereDate` on `planned_departure_at`.
- Bug: `CashForecastQuery::bucketize()` drops all overdue (`$index < 0`) items instead of clamping into week 0.

Useful context for future reviews:
- `php artisan performance:audit --static --no-alert` PASSES (53 pages, 50 budgeted, 0 broken). It only checks budgets *exist* + registers call `paginate()`; `scripts/perf-budget.php` (actual query-count measurement) is NOT in `composer ci:check`.
- Verified NOT bugs: `NumberAllocator` (`lockForUpdate` + transaction guard) is concurrency-safe; Laravel 13 `ManagesTransactions::handleTransactionException` converts nested concurrency errors to `DeadlockException`, so nested `DB::transaction(...,3)` in `LedgerService::post()` does not silently lose writes; `LedgerVerifier` cross-tenant raw SQL is deliberate; money stays integer minor units.
- Laravel 13 / PHP 8.5.12 available locally; `config/app.php` timezone is UTC while the business timezone is Africa/Gaborone (a recurring source of date bugs).
